# PathSnap: Map-Matching & Route Reconstruction

UE24CS352A Machine Learning Hackathon (PES University, RR Campus).

PathSnap matches noisy GPS trajectories to a road network. A candidate-scoring
classifier (LightGBM, Bayesian-tuned) rates nearby road arcs for every GPS
observation, and an HMM with Viterbi decoding turns those scores into a
connected route. A FastAPI backend serves predictions, and a browser UI on a
second laptop sends trips to it and shows the results.

```
GPS track + road network
  -> clean track (invalid / unordered / duplicate timestamps)
  -> local metric projection (equirectangular about trip centroid)
  -> candidate arcs (KD-tree, radius 60 m, top-8; fallback 300 m)
  -> 22 features per (observation, candidate)
  -> LightGBM probability that candidate is the true arc
  -> HMM / Viterbi (emission = classifier prob, transition = |route dist - GPS dist|)
  -> per-observation arc + connected route (shortest-path gap filling)
```

## Installation

Python 3.10+ (developed on 3.13).

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Reproducing the experiments

Run from the repository root, in this order:

```bash
python scripts/01_eda.py              # inventory, quality checks, EDA figures, Folium EDA map
python scripts/02_build_dataset.py    # label alignment + candidates + features -> data/processed/
python scripts/03_train_compare.py    # 7 models: GroupKFold-5 CV + student-test evaluation
python scripts/04_bayes_opt.py        # Optuna TPE (40 trials) on LightGBM -> models/final/classifier.joblib
python scripts/05_hmm_eval.py         # decoder tuning on train OOF, classifier vs HMM, Folium maps
python scripts/06_figures.py          # all comparison figures from results/
```

Seeds are fixed (`SEED = 42`). `data/processed/` is regenerated by step 2, so it is not committed.

## Running the system (two laptops)

**Laptop 1: model + API**

```bash
# put the 10 evaluator trips in one folder: <dir>/<trip_id>/<trip_id>.track|.nodes|.arcs|.route
set PATHSNAP_EVAL_DIR=C:\path\to\evaluator_test          # Windows
export PATHSNAP_EVAL_DIR=/path/to/evaluator_test         # Linux / macOS
uvicorn api.main:app --host 0.0.0.0 --port 8000
```

Find Laptop 1's IP address (`ipconfig` / `ip a`) and allow port 8000 through the firewall.
Every request is logged to this console (trip, accuracy, timings), which is the log the evaluators check.

**Laptop 2: UI**

```bash
cd ui
python -m http.server 5500
```

Open `http://localhost:5500`, enter `http://<laptop1-ip>:8000`, click **Connect**, pick a trip, and click **Run prediction**.

### API

| Method | Path | Description |
|---|---|---|
| GET | `/health` | status, loaded HMM config, evaluation folder |
| GET | `/trips` | trip ids + number of GPS points in `PATHSNAP_EVAL_DIR` |
| POST | `/predict` | body `{"trip_id": "...", "use_hmm": true}` → GPS points, predicted route polylines/arc ids, metrics, timings |

```bash
curl http://<laptop1-ip>:8000/trips
curl -X POST http://<laptop1-ip>:8000/predict -H "Content-Type: application/json" -d "{\"trip_id\": \"00000000\"}"
```

### Leakage safeguards

- The prediction path (`PathSnapModel.predict_trip`) builds the trip **without** the route: `load_trip(..., with_route=False)`.
- The `.route` file is read only after prediction, inside the scoring step, and is never sent to the UI.
- No trip IDs or outputs are hardcoded. Evaluator data was never used for training, feature selection or tuning.

## Labels and metrics (summary)

- `.route` is an ordered arc sequence, not per-point labels. Each GPS point gets a reference arc from a **monotone DP alignment** of the track to the route.
- Points more than 50 m from their aligned route arc are flagged unreliable (the reference route does not cover them). They are excluded from training and from point-level scoring, and their coverage is reported.
- **Top-1 accuracy**: the highest-scoring candidate per observation equals the reference arc. This is the primary metric.
- **Macro F1 / precision / recall**: candidate-level binary metrics using the same top-candidate decision rule.
- **Route continuity**: share of consecutive observations whose predicted arcs are the same arc, adjacent, or reachable on the directed network within a plausible distance.
- **Route P/R/F1**: length-weighted overlap between the reconstructed route and the reference route.

See `reports/PathSnap_Technical_Report.pdf` for full results.
